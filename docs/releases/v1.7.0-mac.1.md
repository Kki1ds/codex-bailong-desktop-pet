# macOS 1.7.0-mac.1

基于上游 v1.7.0（14fc85a460de66cad3f7dcbc5e4131130aa2141f）及其后合并的 macOS 路径 PR #28（817ee63d3bfcae87d1ba617a392134e95074303c）。测试设备：MacBook Pro M1 Pro，macOS 27.2.1（arm64），Homebrew Python 3.12.15，PySide6 6.9.2。

## 变化

同步上游 1.6.1 至 1.7.0：今日与实时数字逐位滚动、日报与 24 小时图按模型着色并显示回合速率中位数、周额度对照选择更合适的历史周期、实时与额度浮窗布局统一、续写会话重启后漏报与已读后提醒未消失的修复，以及 Token 汇总和图表刷新的性能改进。

Mac 专属部分保持不变：钥匙串、数据与资源路径、Codex CLI 发现与 Unix IPC、会话跳转、登录启动（LaunchAgent）、跨桌面空间与全屏让位、应用内更新关闭。

- 上游已自行修复“任务完成后同一 turn 补写的后台命令记录让状态一直忙碌”（上游 #25），Mac 版改用上游实现，原 fork 回归测试保留并通过。
- `platform_paths` 现由上游与 fork 共用：采用上游的数据目录接口，保留 Mac 的登录启动、应用资源路径等辅助函数；macOS 数据目录仍为 `~/Library/Application Support/BailongEnhanced`。
- 打包加入上游新增的 `cryptography` 依赖（ChatGPT 套餐登录验签）。

## 自动测试（2026-11-14）

- `python -m compileall -q app tools build_macos.py`：通过。
- `tools/check_source.py --macos`：95 个模块、1074 项测试全部成功（包含显式平台跳过；最终列表含按复核建议加入的 `test_chatgpt_service`），每个模块独立进程、隔离用户目录和 Codex 目录。
- 上游新纳入源码测试的 4 个模块在纯上游 v1.7.0 上于 Mac 同样失败，属平台差异；本版做了以下适配，不放宽生产规则：DWM 呈现屏障只在 win32 调用；Windows 部署测试的临时目录在 Mac 上解析 `/var` 系统别名；更新取消测试使用与同文件一致的 Windows 更新流程夹具；卡片互补混合测试在非 Windows 上允许 alpha 253（Apple Silicon 光栅取整在混合中段恒定少 2，变异回 source-over 时降到 246，仍能检出原缺陷）。
- 源码隔离实例 `--smoke-test --settings` 启动设置页并自动退出，退出码 0，错误日志为空。
- 冻结 `.app` 以隔离数据执行同样的启动检查，退出码 0，错误日志为空，生成 1.7.0 运行快照；未写入真实数据目录或真实 LaunchAgents。
- `build_macos.py --cards-only --dmg` 构建成功；`codesign --verify --deep --strict` 通过；DMG 镜像校验与 `shasum -a 256 -c` 通过。

## 独立复核（2026-11-14）

原计划由本机 Codex 复核：以 `codex exec` 在本分支发起后，Codex 自动派出 3 个子代理，约两分钟后因 Codex 账户用量上限中断，未给出结论；中途仅指出 `test_enhanced_core` 在 macOS 测试列表中重复执行，已修正。随后改由另一个独立复核代理在同一台 Mac 上完成，结论为**通过**，无阻塞问题：

- Mac 专属代码保留清单逐项核对通过：钥匙串读写删、`app_root` 资源路径、WSL 守卫（`data_home` 与上游 #28 一致）、全屏让位跳过系统辅助进程、`desktop_services` 分支顺序、macOS 应用内更新关闭及设置页文案、`BUNDLE_ID`。
- `platform_paths` 同时保留 fork 辅助函数与上游 `fallback` 语义，调用方检查无误；`enhanced_core.py` 与上游逐字节一致，fork 回归用例存在且无同名覆盖。
- 上游新代码在 macOS 上的数据写入都经 `platform_paths`；Windows 安装器模块的主目录回退只在 Windows 路径使用，macOS 上被平台守卫挡住，实测主目录下没有生成 BailongEnhanced。
- 4 处测试适配均判定合理、未掩盖真实缺陷；ChatGPT 套餐凭据与闲聊密钥共用钥匙串服务名，但清理逻辑只删除对应服务商的条目，不会误删。按复核建议把 `test_chatgpt_service` 加入 `check_source.py --macos`。
- 复核重跑：编译检查通过；`check_source.py --macos` 94 个模块、1069 项全部成功；`test_chatgpt_service` 5 项通过；`BAILONG_KEYCHAIN_TEST=1` 下钥匙串临时条目测试 8 项通过（独立服务名，自动清理，未触碰真实条目）。
- 真机检查：源码与冻结 `.app` 隔离启动均退出码 0、错误日志为空、无残留进程；签名、DMG 哈希、版本号与 `cryptography` 打包确认；本机 Codex CLI（ChatGPT.app 内置，0.167.0-alpha.4.1）发现与只读联动正常；登录启动 plist 生成在隔离目录，Label、启动参数、RunAtLoad、Aqua 会话限制与进程组设置正确，未加载到 launchd。
- 低风险建议（未阻塞，留待后续）：如手工把闲聊服务商 id 改成 `active`，清除其密钥时会删到 ChatGPT 套餐凭据；界面不会生成这种 id。

## 未人工验收

以下项目需要人眼确认，本版未在 1.7.0 上重新人工验收（1.6.0-mac.1 的人工验收结果见 [该版记录](v1.6.0-mac.1.md)）：

- Chrome 原生/视频全屏让位与退出恢复，完成提醒不抢回显示。
- 切换桌面空间时人物与卡片跟随、不抢焦点；多屏混合缩放下拖动与贴边。
- 深色模式外观；新浮窗与主题切换的视觉效果。
- 真实 Codex 任务的进行中显示、完成提醒、已读与跳转。
- 开启登录启动后注销再登录的自动启动；钥匙串授权弹窗。
- 上游新增的“ChatGPT 套餐”闲聊预览（浏览器授权、凭据存入登录钥匙串）未在 Mac 上测试。
- 高清素材下载与动作边界切换、Chrome 前台时的窗口避让路线；本版未测量性能。
